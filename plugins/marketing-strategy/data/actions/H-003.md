## Draft body

```markdown
Every team I've spoken to that deployed Claude Code at scale hit the same wall: individual developers have great workflows, but nothing is shared, nothing is governable, and leadership has zero visibility into what AI is being used for.

The conversation I keep having with VPs of Eng at 100-300-person companies:

"We bought Claude Code licences. Developers love it. We have no idea which teams use it, what for, how much it costs, or whether the same skills are being reinvented across five teams. Our security team is asking about agent governance and we don't have an answer."

I wrote a guide on what a governance rollout actually looks like in practice: https://systemprompt.io/guides/claude-code-organisation-rollout

Short version:

1. **Start with a skill marketplace, not a policy document.** If you give devs a curated library of coding-standard skills, review skills, deployment skills, they'll use them. If you give them a policy doc, they won't read it.
2. **Central MCP server registry.** Every team configuring their own MCP servers locally means zero governance and constant drift. One registry, one auth model, per-role distribution.
3. **Usage analytics by department.** You need to be able to tell leadership "team A uses Claude for code review, team B uses it for customer comms, team C barely touches it." Without this you can't justify expanding the budget or cutting it.
4. **Audit trails with identity propagation.** Not for compliance reporting, for understanding. Who invoked which agent, using which tools, for what.
5. **Eventually you do need a governance layer** — but you need it after adoption, not before it.

Interested in how others are solving this. What did you try that worked? What didn't?

(Disclosure: I work on systemprompt.io, which is one way to solve points 1-4 above as a self-hosted Rust binary. Happy to answer questions but the above is how I'd approach it with or without our tool.)
```
